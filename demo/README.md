# Record Payroom

Use the real browser and actual receipts. Record at 1440 by 1000 or a comparable readable desktop viewport, then export H.264 MP4 with captions and a separate SRT. No narration or generated product footage.

`baseline.json` starts with the controls explanation. `candidate.json` starts with an invoice and shows the useful action sooner. They are two plans for the same workflow, not two measured recordings. Actual browser latency and caption readability must be measured after recording.

## Preconditions

- The local workspace runs and contains enough pUSD for one small invoice.
- Use a unique DEMO reference, a plainly labelled test contributor and 12.50 pUSD. Do not delete previous receipts to make a recording look new.
- Show Local Anvil in the recording until the actual Sepolia/KeeperHub release is available.
- Keep the full transaction result visible. A waiting or failed run is not a payment.
- Record the local flow now if sponsor access waits. Label it a local preview, and do not submit it as the required live integration video.

## Final sponsor sequence

After live release, replace the local keeper scene with the actual KeeperHub request or workflow run. Show the verified Sepolia receipt and the invoice paid state, with matching invoice ID and transaction hash. Demonstrate the duplicate guard without making a misleading edited claim about a second transfer. Keep sponsor credentials and account security screens out of the recording.

The event asks for a short video showing the integration working and a transaction executed through KeeperHub. The final video must include that proof. A sponsor logo or adapter code alone does not meet it.

## Review each take

Measure duration, first useful action, caption characters per second, overlaps and timing against actual actions. A 12 to 17 characters-per-second target is a trial starting point, not a validated preference. Keep the first failed take and its reason. Decode the full exported MP4, play it in a browser, inspect caption placement and read the transaction result at normal speed. Save actual metadata and the record export beside the recording evidence.
